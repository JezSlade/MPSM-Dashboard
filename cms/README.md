# CMS Layer

Verified against the working tree on 2026-05-20.

## Purpose

`cms/` is the browser-facing dashboard application. It contains the main dashboard pages, login page, legacy JSON endpoints, the REST v1 gateway, static assets, local cache files, cron helpers, and operational diagnostics.

## Active Entry Points

- [index.php](index.php) - main dashboard.
- [login.html](login.html) - login form.
- [functions.php](functions.php) - shared procedural helpers for auth, database access, MPS API calls, preferences, cache helpers, and JSON responses.
- [config.php.example](config.php.example) - template for the local `config.php` file.
- [api/login.php](api/login.php) and [api/logout.php](api/logout.php) - session authentication endpoints.
- [api/v1/index.php](api/v1/index.php) - REST v1 gateway backed by `bootstrap.php` and `src/` classes.

## Main Subdirectories

```text
cms/
├── api/             # Legacy endpoints, diagnostics, cache refresh, REST v1
├── assets/          # Dashboard JavaScript and CSS
├── archive/         # Archived one-off fix scripts
├── data/            # Runtime JSON state, ignored by git
├── locks/           # Runtime cache refresh locks/state, ignored by git
└── logs/            # Runtime logs, ignored by git
```

## Configuration

Legacy CMS files include `cms/config.php`, which is deployment-local and ignored by git because it contains environment-specific credentials and constants. Use [config.php.example](config.php.example) as the template.

The newer REST/service layer uses repository-managed [../config/app.php](../config/app.php), which reads `.env` through [../config/env.php](../config/env.php).

## Runtime Data

These paths are generated by the live application and should not be committed:

- `api/cache/*.json`
- `data/*.json`
- `locks/*`
- `logs/*`
- `error_log`
- `config.php`
- `config.php.backup.*`

## Verification Notes

- The older claim that this layer has only 12 files is no longer true; `cms/` currently contains hundreds of source, diagnostic, archive, cache, and log files.
- The older claim that there is no cache is no longer true; both `cms/api/cache/*.json` and `mps-api/cache/ActionCache.php` are present.
- `login.html`, not `login.php`, is the browser login page. `api/login.php` is the login API.
